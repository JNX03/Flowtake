# Flowtake Launch Kit

This folder keeps the assets and copy for a focused open-source launch push.
The goal is simple: make the GitHub repo easy to understand in under 20 seconds,
then give people a clear reason to star, try, and share Flowtake.

## Positioning

Flowtake is a free, local, open-source screen recorder that automatically turns
raw recordings into polished product demos with smooth zooms, pans, cursor
motion, captions, masks, and export presets.

Primary hook:

> Screen Studio-style recordings, but free, local, open source, and cross-platform.

## Audience

- Indie hackers and founders making product demos.
- Open-source maintainers recording tutorials or issue repros.
- Developer advocates making short technical videos.
- Windows and Linux users who want Screen Studio-style polish.
- Privacy-conscious teams that prefer local recording and editing.

## 100-Star Sprint

1. Make the README visually convincing with demo media and screenshots.
2. Publish one sincere launch post per channel instead of blasting duplicates.
3. Drive every post to the GitHub repo, not a generic landing page.
4. Ask for specific feedback: recording bugs, platform gaps, and auto-zoom tuning.
5. Reply fast to comments with examples, fixes, and short clips.
6. Convert early feedback into GitHub issues and visible follow-up commits.

## Channel Order

| Priority | Channel | Why |
| --- | --- | --- |
| 1 | Hacker News Show HN | Strong fit for open-source developer tools |
| 2 | Reddit | Good for targeted feedback from makers and Linux/Windows users |
| 3 | Product Hunt | Best after the README, demo, and release assets are polished |
| 4 | X / Bluesky / LinkedIn | Good for founder/devrel reach and second-wave sharing |
| 5 | GitHub Discussions / issues | Good for collecting roadmap and platform feedback |

## Approval Checklist

Before any public post goes live:

- Confirm the exact account to use.
- Confirm the title and post body.
- Confirm the demo media attached to the post.
- Confirm whether comments should ask for stars, feedback, or both.
- Do one final check that release downloads still work.

Public posts should not claim star counts, download counts, platform stability, or
feature completeness unless those claims were freshly verified.
